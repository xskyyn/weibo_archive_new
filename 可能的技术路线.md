在 FastAPI + SQLAlchemy 2.0 的异步架构下，配置 SQLite 的 FTS5 全文搜索 有一个核心难点：SQLAlchemy 原生对 FTS5 虚拟表的支持较弱，且 SQLite 默认的 FTS5 对中文分词支持极差（它会把“我喜欢猫”拆成“我”、“喜”、“欢”、“猫”，导致搜索“喜欢”时搜不到）。

为了解决这个问题，我为你设计了这套 “Python 层分词 + SQLite 触发器自动同步” 的最佳实践方案。

FTS5 全文搜索引擎配置 (核心亮点)

定义创建 FTS5 虚拟表和触发器的原生 SQL
注意：这里使用 content="posts" 和 content_rowid="id" 将虚拟表与主表绑定
FTS5_SETUP_SQL = """
-- 创建 FTS5 虚拟表，仅索引 search_text 字段
CREATE VIRTUAL TABLE IF NOT EXISTS posts_fts USING fts5(
    search_text, 
    content="posts", 
    content_rowid="id",
    tokenize="unicode61"
);

-- 创建触发器：当 posts 表插入新数据时，自动同步到 FTS5 表
CREATE TRIGGER IF NOT EXISTS posts_ai AFTER INSERT ON posts BEGIN
    INSERT INTO posts_fts(rowid, search_text) VALUES (new.id, new.search_text);
END;

-- 创建触发器：当 posts 表数据删除时，自动从 FTS5 表删除
CREATE TRIGGER IF NOT EXISTS posts_ad AFTER DELETE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, search_text) VALUES('delete', old.id, old.search_text);
END;

-- 创建触发器：当 posts 表数据更新时，自动更新 FTS5 表
CREATE TRIGGER IF NOT EXISTS posts_au AFTER UPDATE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, search_text) VALUES('delete', old.id, old.search_text);
    INSERT INTO posts_fts(rowid, search_text) VALUES (new.id, new.search_text);
END;
"""

使用 SQLAlchemy 的 event 监听器，在 Base 的 metadata 创建完毕后，自动执行上述原生 SQL
@event.listens_for(Base.metadata, "after_create")
def create_fts5_triggers(target, connection, **kw):
    # 注意：在异步环境下，这里的 connection 是同步的底层 DBAPI connection
    # 我们需要将其包装或直接执行原生 SQL
    for stmt in FTS5_SETUP_SQL.split(';'):
        if stmt.strip():
            connection.execute(text(stmt))

def clean_and_tokenize(html_text: str) -> str:
    """
    清洗 HTML 标签，并使用 jieba 进行中文分词，返回用空格隔开的字符串。
    这是解决 SQLite FTS5 中文搜索痛点的关键！
    """
    if not html_text:
        return ""
    
    # 1. 移除 HTML 标签 (如 <br />, <span class="url-icon"> 等)
    clean_text = re.sub(r'<[^>]+>', '', html_text)
    
    # 2. 移除多余的空白字符
    clean_text = re.sub(r's+', ' ', clean_text).strip()
    
    # 3. 使用 jieba 进行精确模式分词
    # 例如："我喜欢吃苹果" -> "我 喜欢 吃 苹果"
    # FTS5 的 unicode61 tokenizer 会按空格拆分词组，这样就能完美匹配中文词汇了！
    words = jieba.lcut(clean_text, cut_all=False)
    
    # 过滤掉单个字的停用词（可选，视需求而定，这里保留所有词）
    return " ".join(words)

async def init_db():
    """
    初始化数据库，创建所有表并配置 FTS5。
    应在 FastAPI 的 lifespan 或 startup 事件中调用。
    """
    async with engine.begin() as conn:
        # run_sync 用于在异步环境中执行同步的 metadata.create_all
        await conn.run_sync(Base.metadata.create_all)

async def get_db():
    """
    FastAPI 的依赖注入项，用于获取数据库 Session。
    """
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
        finally:
            await session.close()

@app.get("/search/")
async def search_posts(keyword: str, db: AsyncSession = Depends(get_db)):
    """
    测试 FTS5 全文搜索。
    例如：搜索 "小猫" 或 "公园"
    """
    # 使用 SQLAlchemy 的 text() 执行原生 FTS5 查询
    # MATCH 是 FTS5 的核心语法
    query = text("""
        SELECT p.id, p.text, p.created_at 
        FROM posts p
        JOIN posts_fts ON p.id = posts_fts.rowid
        WHERE posts_fts MATCH :keyword
        ORDER BY p.created_at DESC
    """)
    
    result = await db.execute(query, {"keyword": keyword})
    posts = result.fetchall()
    
    return {"count": len(posts), "results": [dict(row._mapping) for row in posts]}

💡 核心设计原理解析（避坑指南）

为什么不用 SQLAlchemy 的 __table_args__ 直接定义 FTS5？
   SQLAlchemy 对 SQLite 特有的虚拟表（Virtual Table）支持非常有限。强行用 ORM 定义会导致 create_all 报错。使用 @event.listens_for 监听 after_create 事件，并在底层执行原生 SQL 是最稳妥、最优雅的做法。

为什么需要 clean_and_tokenize (jieba 分词)？
   SQLite FTS5 默认的 unicode61 分词器是按空格和标点分词的。如果你直接把 "我喜欢猫" 存进去，它会把它当成一个完整的长词。当你搜索 "喜欢" 时，FTS5 会认为不匹配。
   我们的解决方案：在 Python 层用 jieba 把 "我喜欢猫" 变成 "我 喜欢 猫" 存入 search_text 字段。FTS5 就会把它拆成三个独立的词。当你搜索 "喜欢" 时，完美命中！

触发器 (Triggers) 的魔力：
   我们在 SQL 中写了 AFTER INSERT/UPDATE/DELETE 触发器。这意味着在你的 Python 爬虫代码中，你只需要像平常一样 db.add(post) 和 await db.commit()，SQLite 会在底层自动帮你把数据同步到 posts_fts 索引表中。你完全不需要在 Python 代码里手动维护两份数据，彻底解耦！

太棒了！接下来我们进入爬虫引擎的核心：网络请求与风控对抗层。

在微博爬虫中，直接发请求往往会遇到以下几个“坑”：
XSRF-TOKEN 过期：微博移动端接口强制校验 XSRF-TOKEN，且有时效性，必须定期刷新。
风控与验证码 (-100)：请求过快或环境异常时，微博会返回 code: -100 并要求滑块验证。
HTTP 418/403 封禁：IP 或 Cookie 被临时拉黑。

为了解决这些问题，我们将使用 httpx (异步请求) + tenacity (优雅重试) 来封装一个健壮的 WeiboClient。

class WeiboClient:
    def init(self, cookie_path: str = "cookie.json", workspace_dir: Path = Path("workspace")):
        self.cookie_path = Path(cookie_path)
        self.workspace_dir = workspace_dir
        self.workspace_dir.mkdir(exist_ok=True)
        
        # 加载 Cookie
        self.cookies: Dict[str, Any] = self._load_cookies()
        
        # 初始化 httpx 异步客户端
        # 设置较长的超时时间，微博服务器有时响应很慢
        timeout = httpx.Timeout(30.0, connect=10.0)
        self.client = httpx.AsyncClient(
            headers=self._get_default_headers(),
            timeout=timeout,
            follow_redirects=True
        )
        
        # 状态标记
        self._is_token_refreshing = False

    def _get_default_headers(self) -> Dict[str, str]:
        """伪装成 Android 移动端 Chrome"""
        return {
            "authority": "m.weibo.cn",
            "accept": "application/json, text/plain,/",
            "accept-language": "zh-CN,zh;q=0.9,en-US;q=0.8,en;q=0.7",
            "cache-control": "no-cache",
            "mweibo-pwa": "1",
            "origin": "https://m.weibo.cn",
            "pragma": "no-cache",
            "referer": "https://m.weibo.cn/compose/",
            "sec-ch-ua": '"Not_A Brand";v="8", "Chromium";v="120", "Google Chrome";v="120"',
            "sec-ch-ua-mobile": "?1",
            "sec-ch-ua-platform": '"Android"',
            "sec-fetch-dest": "empty",
            "sec-fetch-mode": "cors",
            "sec-fetch-site": "same-origin",
            "user-agent": "Mozilla/5.0 (Linux; Android 13; Pixel 7) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/116.0.0.0 Mobile Safari/537.36",
            "x-requested-with": "XMLHttpRequest",
        }

    def _load_cookies(self) -> Dict[str, Any]:
        """从本地 JSON 文件加载 Cookie"""
        if not self.cookie_path.exists():
            logger.warning(f"未找到 {self.cookie_path}，将使用空 Cookie。请手动登录或导入。")
            return {"MLOGIN": 1} # 强制标记为已登录状态尝试
        
        with open(self.cookie_path, "r", encoding="utf-8") as f:
            data = json.load(f)
            # 兼容直接是 dict 或者包含 weibo.cn 键的格式
            if "weibo.cn" in data:
                cookies = data["weibo.cn"]
            else:
                cookies = data
            cookies["MLOGIN"] = 1
            return cookies

    def _save_cookies(self):
        """将更新后的 Cookie 保存回本地"""
        with open(self.cookie_path, "w", encoding="utf-8") as f:
            json.dump(self.cookies, f, ensure_ascii=False, indent=2)

    async def refresh_token(self) -> Optional[str]:
        """
        刷新 XSRF-TOKEN。
        微博的 XSRF-TOKEN 有时效性，通过请求 /api/config 获取最新的 st 值。
        """
        if self._is_token_refreshing:
            return self.cookies.get("XSRF-TOKEN")
            
        self._is_token_refreshing = True
        try:
            logger.info("[-] 正在刷新 XSRF-TOKEN...")
            # 更新时间水印
            import time
            self.cookies["_T_WM"] = int(time.time() / 3600) * 100001
            
            url = "https://m.weibo.cn/api/config"
            resp = await self.client.get(url, cookies=self.cookies)
            resp.raise_for_status()
            
            data = resp.json().get("data", {})
            if not data.get("login", False):
                logger.error("[!] Cookie 可能无效，未检测到登录状态！")
                raise WeiboAuthError("Cookie 无效或未登录")
                
            new_token = data.get("st")
            if new_token:
                self.cookies["XSRF-TOKEN"] = new_token
                self._save_cookies()
                logger.info(f"[-] XSRF-TOKEN 刷新成功: {new_token[:10]}...")
                return new_token
            return None
        finally:
            self._is_token_refreshing = False

    def _get_request_headers(self, referer: str = "") -> Dict[str, str]:
        """构建带 Cookie 和 Token 的请求头"""
        headers = {}
        if referer:
            headers["referer"] = referer
            
        # 拼接 Cookie 字符串
        cookie_str = "; ".join([f"{k}={v}" for k, v in self.cookies.items()])
        headers["cookie"] = cookie_str
        headers["x-xsrf-token"] = self.cookies.get("XSRF-TOKEN", "")
        
        return headers

    @retry(
        stop=stop_after_attempt(3),
        wait=wait_exponential(multiplier=1, min=2, max=10),
        retry=retry_if_exception_type((httpx.TimeoutException, WeiboRateLimitError)),
        before_sleep=before_sleep_log(logger, logging.WARNING),
        reraise=True
    )
    async def _request(
        self, 
        url: str, 
        referer: str = "", 
        max_retries_on_captcha: int = 1
    ) -> httpx.Response:
        """
        核心请求方法。包含随机延迟、风控检测与自动重试。
        """
        # 1. 随机延迟 (0.7s ~ 1.5s)，模拟人类操作
        await asyncio.sleep(random.uniform(0.7, 1.5))
        
        headers = self._get_request_headers(referer)
        
        # 2. 发送请求
        resp = await self.client.get(url, headers=headers)
        
        # 3. HTTP 状态码风控检测
        if resp.status_code in [418, 403, 429]:
            logger.warning(f"[!] 触发 HTTP 风控 ({resp.status_code})，准备重试...")
            raise WeiboRateLimitError(f"HTTP {resp.status_code}")
            
        resp.raise_for_status()
        
        # 4. 业务逻辑风控检测 (JSON 解析)
        # 注意：有些接口返回的不是 JSON，这里需要容错
        try:
            json_data = resp.json()
        except json.JSONDecodeError:
            return resp # 如果不是 JSON（如下载文件），直接返回
            
        # 检查微博特有的风控 code
        code = json_data.get("code")
        ok = json_data.get("ok")
        
        if code == -100 or ok == -100:
            captcha_url = json_data.get("url", "")
            logger.error(f"[!] 触发验证码 (-100): {captcha_url}")
            # 抛出验证码异常，交由上层的 TaskManager 暂停任务并通知前端
            raise WeiboCaptchaError(url=captcha_url, msg=json_data.get("msg", "需要验证"))
            
        # 检查 Token 是否过期 (通常表现为 ok != 1 且提示登录)
        if ok != 1 and "login" in json_data.get("msg", "").lower():
            logger.warning("[!] Token 可能过期，尝试刷新...")
            await self.refresh_token()
            # 刷新后重试当前请求 (通过 tenacity 抛出异常触发重试，或者直接递归调用)
            raise WeiboRateLimitError("Token expired, retrying...")
            
        return resp

    async def get_json(
        self, 
        url: str, 
        referer: str = "", 
        all_ret: bool = False
    ) -> Dict[str, Any]:
        """
        发起 GET 请求并返回解析后的 JSON 数据。
        默认只返回 data 字段，若 all_ret=True 则返回完整响应。
        """
        resp = await self._request(url, referer=referer)
        data = resp.json()
        
        if all_ret:
            return data
            
        # 微博接口通常把真实数据放在 "data" 键下
        return data.get("data", {})

    async def download_file(self, url: str, save_path: Path, referer: str = "https://weibo.com/") -> bool:
        """
        异步流式下载媒体文件 (图片/视频)。
        """
        if save_path.exists():
            return True # 已存在则跳过
            
        save_path.parent.mkdir(parents=True, exist_ok=True)
        
        headers = {"referer": referer}
        try:
            # 使用 stream=True 避免大文件撑爆内存
            async with self.client.stream("GET", url, headers=headers, timeout=60.0) as resp:
                resp.raise_for_status()
                with open(save_path, "wb") as f:
                    async for chunk in resp.aiter_bytes(chunk_size=8192):
                        f.write(chunk)
            logger.debug(f"[+] 下载成功: {save_path.name}")
            return True
        except Exception as e:
            logger.error(f"[!] 下载失败 {url}: {e}")
            if save_path.exists():
                save_path.unlink() # 清理损坏的文件
            return False

    async def close(self):
        """关闭客户端连接"""
        await self.client.aclose()

💡 核心设计亮点解析

tenacity 优雅重试机制：
   使用 @retry 装饰器，当遇到 httpx.TimeoutException（网络超时）或 WeiboRateLimitError（418/403 封禁）时，自动进行指数退避重试（等待 2s, 4s, 8s...）。
   这比手写 while True + sleep 优雅得多，且不会阻塞其他异步任务。

风控熔断 (WeiboCaptchaError)：
   当检测到 code: -100（需要滑块或短信验证）时，不自动重试（因为重试也没用），而是直接抛出 WeiboCaptchaError。
   下一步联动：你的 FastAPI 后台任务管理器（TaskManager）捕获到这个异常后，会将任务状态标记为 PAUSED_CAPTCHA，并通过 WebSocket 把 captcha_url 推送到 Vue 前端，弹出验证码窗口让用户手动处理。

XSRF-TOKEN 自动续期：
   微博的 XSRF-TOKEN 很容易过期。refresh_token 方法通过请求 /api/config 获取最新的 st 值，并自动更新内存和本地 cookie.json。
   如果请求时发现 ok != 1 且提示登录，会自动触发刷新并重试。

异步流式下载 (download_file)：
   使用 client.stream 和 aiter_bytes，即使下载 1GB 的高清视频，内存占用也只会保持在几 MB 级别，非常适合长时间挂机归档。

现在你有了数据库模型 (database.py) 和 网络请求引擎 (client.py)。

接下来，我们需要一个任务调度器 (TaskManager)。因为归档是一个耗时任务，不能在 FastAPI 的 HTTP 请求线程里同步执行，必须把它放到后台（Background Task），并且要支持暂停、恢复、断点续传和实时进度推送 (WebSocket)。

这是连接“底层爬虫”与“前端 UI”的最关键桥梁：异步任务调度与实时通信中心。

在 FastAPI 中处理耗时任务（如归档几万条微博），绝对不能阻塞主线程。我们需要一个 TaskManager，它负责：
后台异步执行：将爬虫逻辑放入 asyncio.create_task，不阻塞 API 响应。
状态机管理：精准控制任务状态（运行、暂停、等待验证码、完成）。
断点续传：记录抓取进度（since_id），随时中断随时恢复。
WebSocket 实时广播：将日志和进度条数据实时推送到 Vue 前端。

class ArchiveTaskManager:
    def init(self):
        self.status: TaskStatus = TaskStatus.IDLE
        self.current_uid: Optional[int] = None
        
        # 任务控制
        self._task: Optional[asyncio.Task] = None
        self._stop_event = asyncio.Event()
        self._resume_event = asyncio.Event()
        self._resume_event.set() # 初始状态为可运行
        
        # 进度统计
        self.total_fetched = 0
        self.current_page = 1
        
        # WebSocket 连接池 (支持多个前端页面同时查看日志)
        self.active_connections: Set[WebSocket] = set()
        
        # 爬虫客户端 (延迟初始化)
        self.client: Optional[WeiboClient] = None

    async def connect(self, websocket: WebSocket):
        """接受 WebSocket 连接"""
        await websocket.accept()
        self.active_connections.add(websocket)
        # 连接成功后，立即推送当前状态，让前端同步
        await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))

    def disconnect(self, websocket: WebSocket):
        """断开 WebSocket 连接"""
        self.active_connections.discard(websocket)

    async def _send_ws(self, message: WSMessage):
        """向所有连接的前端广播消息"""
        if not self.active_connections:
            return
        dead_connections = set()
        for connection in self.active_connections:
            try:
                await connection.send_json(message.model_dump())
            except Exception:
                dead_connections.add(connection)
        self.active_connections -= dead_connections

    async def log(self, msg: str, level: str = "info"):
        """统一日志处理：打印到控制台 + 推送到前端"""
        if level == "error":
            logger.error(msg)
            await self._send_ws(WSMessage(type=WSMessageType.ERROR, data=msg))
        else:
            logger.info(msg)
            await self._send_ws(WSMessage(type=WSMessageType.LOG, data=msg))

    # ==========================================
    # 3. 任务生命周期控制
    # ==========================================
    async def start(self, uid: int):
        """启动归档任务"""
        if self.status == TaskStatus.RUNNING:
            await self.log("[!] 任务已在运行中，请勿重复启动。", "error")
            return

        self.current_uid = uid
        self.status = TaskStatus.RUNNING
        self._stop_event.clear()
        self._resume_event.set()
        
        if not self.client:
            self.client = WeiboClient()

        # 将核心抓取逻辑放入后台任务
        self._task = asyncio.create_task(self._archive_loop())
        await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))
        await self.log(f"🚀 开始归档用户 {uid} 的微博数据...")

    async def stop(self):
        """安全停止任务"""
        if self.status != TaskStatus.RUNNING and self.status != TaskStatus.PAUSED_CAPTCHA:
            return
            
        await self.log("🛑 正在安全停止任务，等待当前请求完成...")
        self._stop_event.set()
        self._resume_event.set() # 如果正处于暂停状态，唤醒它以便让它检查 stop_event 并退出
        
        if self._task:
            try:
                await asyncio.wait_for(self._task, timeout=10.0)
            except asyncio.TimeoutError:
                self._task.cancel()
        
        self.status = TaskStatus.STOPPED
        await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))

    async def pause_for_captcha(self, captcha_url: str):
        """遇到验证码，暂停任务并通知前端"""
        self.status = TaskStatus.PAUSED_CAPTCHA
        self._resume_event.clear() # 阻塞后续请求
        await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))
        await self._send_ws(WSMessage(type=WSMessageType.CAPTCHA, data=captcha_url))
        await self.log(f"⚠️ 触发风控！请在前端完成验证码: {captcha_url}", "error")

    async def resume(self):
        """用户完成验证码后，恢复任务"""
        if self.status != TaskStatus.PAUSED_CAPTCHA:
            return
            
        self.status = TaskStatus.RUNNING
        self._resume_event.set() # 解除阻塞
        await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))
        await self.log("✅ 验证码处理完毕，恢复抓取...")

    # ==========================================
    # 4. 核心后台抓取循环 (示例逻辑)
    # ==========================================
    async def _archive_loop(self):
        """
        后台持续运行的抓取逻辑。
        实际项目中，这里会调用 parser.py 解析具体的微博接口。
        """
        try:
            # 1. 获取或创建用户
            async with AsyncSessionLocal() as db:
                user = await db.get(User, self.current_uid)
                if not user:
                    user = User(id=self.current_uid, screen_name="抓取中...")
                    db.add(user)
                    await db.commit()

            # 2. 模拟分页抓取循环
            page = 1
            while not self._stop_event.is_set():
                # 检查是否被暂停 (等待验证码)
                await self._resume_event.wait() 
                if self._stop_event.is_set():
                    break

                try:
                    await self.log(f"📄 正在抓取第 {page} 页...")
                    
                    # 【核心调用】这里替换为你真实的 API 调用
                    # 例如: data = await self.client.get_json(f"https://m.weibo.cn/api/container?containerid=107603{self.current_uid}&page={page}")
                    
                    # --- 模拟网络请求与数据写入 ---
                    await asyncio.sleep(1.5) # 模拟网络延迟
                    
                    # 模拟插入数据
                    async with AsyncSessionLocal() as db:
                        # 实际业务中，这里解析 JSON 并 bulk_save
                        # 这里仅作演示
                        self.total_fetched += 10 
                        
                    # 推送进度
                    await self._send_ws(WSMessage(
                        type=WSMessageType.PROGRESS, 
                        data={"page": page, "total_fetched": self.total_fetched}
                    ))
                    
                    # 模拟最后一页
                    if page >= 5: 
                        await self.log("🎉 已到达最后一页，抓取完成！")
                        break
                        
                    page += 1

                except WeiboCaptchaError as e:
                    # 捕获验证码异常，暂停任务
                    await self.pause_for_captcha(e.url)
                    # 注意：这里不要 break，等待 resume() 唤醒后继续循环
                    
                except WeiboRateLimitError as e:
                    await self.log(f"⚠️ 触发频率限制，等待 30 秒后重试...", "error")
                    await asyncio.sleep(30)
                    
                except Exception as e:
                    await self.log(f"❌ 发生未知错误: {str(e)}", "error")
                    self.status = TaskStatus.FAILED
                    break

            # 循环结束后的收尾
            if self.status == TaskStatus.RUNNING:
                self.status = TaskStatus.COMPLETED
                await self.log("🏁 归档任务圆满完成！")
                
        except asyncio.CancelledError:
            await self.log("任务被强制取消。")
        except Exception as e:
            self.status = TaskStatus.FAILED
            await self.log(f"💥 任务崩溃: {str(e)}", "error")
        finally:
            await self._send_ws(WSMessage(type=WSMessageType.STATUS, data=self.status))

💡 核心设计亮点解析 (避坑指南)

asyncio.Event 的妙用 (暂停/恢复机制)：
   很多新手在写暂停功能时，会用 while status == PAUSED: await asyncio.sleep(1)，这不仅浪费 CPU，而且响应慢。
   这里使用了 _resume_event。当遇到验证码时，调用 _resume_event.clear()。在抓取循环中，await self._resume_event.wait() 会零 CPU 消耗地挂起协程。当用户在前端点完验证码，后端调用 resume() 触发 _resume_event.set()，协程瞬间恢复执行，极其优雅！

全局单例 task_manager：
   归档任务必须是全局唯一的（同一时间只能有一个用户在跑归档，否则 IP 必被封）。因此我们实例化了一个全局的 task_manager = ArchiveTaskManager()，所有的 API 和 WebSocket 都操作这一个实例。

WebSocket 连接池管理：
   前端用户可能会刷新页面，或者同时打开两个标签页。active_connections: Set[WebSocket] 确保了无论有多少个前端连着后端，日志都能准确广播给所有人。并且加入了死连接自动清理机制。

安全的停止机制 (_stop_event)：
   当用户点击“停止”时，如果直接 task.cancel()，可能会导致正在写入 SQLite 的事务中断，造成数据库损坏。
   我们的做法是设置 _stop_event.set()，让 _archive_loop 在下一次循环开始时自然检测到该标志位，执行完当前的 db.commit() 后再安全退出。

请将以下代码保存为 backend/scraper/parser.py。它包含了用户信息、微博正文、媒体文件和评论树的完整解析与入库逻辑。

import logging
from typing import List, Dict, Any, Optional
from datetime import datetime

from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select

from backend.database import User, Post, Media, Comment, clean_and_tokenize
from backend.scraper.client import WeiboClient

logger = logging.getLogger("weibo.parser")

class WeiboParser:
    def init(self, client: WeiboClient):
        self.client = client

    # ==========================================
    # 1. 时间字符串解析 (微博特有格式)
    # ==========================================
    @staticmethod
    def parse_weibo_time(time_str: str) -> datetime:
        """
        解析微博各种奇葩的时间格式：
        "刚刚" / "x分钟前" / "x小时前"
        "今天 HH:MM" / "昨天 HH:MM"
        "MM-DD" (跨年时需注意)
        "YYYY-MM-DD HH:MM" (标准格式)
        """
        from datetime import timedelta
        now = datetime.now()
        
        if not time_str:
            return now
            
        try:
            if "刚刚" in time_str:
                return now
            elif "分钟前" in time_str:
                minutes = int(time_str.split("分钟前")[0])
                return now - timedelta(minutes=minutes)
            elif "小时前" in time_str:
                hours = int(time_str.split("小时前")[0])
                return now - timedelta(hours=hours)
            elif "今天" in time_str:
                time_part = time_str.replace("今天", "").strip()
                return datetime.strptime(f"{now.strftime('%Y-%m-%d')} {time_part}", "%Y-%m-%d %H:%M")
            elif "昨天" in time_str:
                time_part = time_str.replace("昨天", "").strip()
                yesterday = now - timedelta(days=1)
                return datetime.strptime(f"{yesterday.strftime('%Y-%m-%d')} {time_part}", "%Y-%m-%d %H:%M")
            elif "-" in time_str and len(time_str) <= 5: 
                # "MM-DD" 格式，默认补全当前年份
                return datetime.strptime(f"{now.year}-{time_str}", "%Y-%m-%d")
            else:
                # 尝试标准格式 "YYYY-MM-DD HH:MM" 或 "YYYY-MM-DD"
                for fmt in ["%Y-%m-%d %H:%M", "%Y-%m-%d"]:
                    try:
                        return datetime.strptime(time_str, fmt)
                    except ValueError:
                        continue
        except Exception as e:
            logger.warning(f"[-] 时间解析失败 '{time_str}': {e}")
            
        return now # 兜底返回当前时间

    # ==========================================
    # 2. 用户信息解析与 Upsert
    # ==========================================
    async def parse_and_save_user(self, db: AsyncSession, user_data: Dict[str, Any]) -> User:
        """解析用户信息，存在则更新，不存在则插入"""
        if not user_data or "id" not in user_data:
            return None
            
        uid = int(user_data["id"])
        stmt = select(User).where(User.id == uid)
        result = await db.execute(stmt)
        user = result.scalar_one_or_none()
        
        if user:
            # 更新现有用户信息
            user.screen_name = user_data.get("screen_name", user.screen_name)
            user.profile_image_url = user_data.get("profile_image_url", user.profile_image_url)
            user.description = user_data.get("description", user.description)
        else:
            # 创建新用户
            user = User(
                id=uid,
                screen_name=user_data.get("screen_name"),
                profile_image_url=user_data.get("profile_image_url"),
                description=user_data.get("description")
            )
            db.add(user)
            
        return user

    # ==========================================
    # 3. 单条微博解析 (核心)
    # ==========================================
    async def parse_post(self, db: AsyncSession, raw_post: Dict[str, Any]) -> Optional[Post]:
        """
        解析单条微博 JSON 并写入数据库。
        包含：基础信息、长文、媒体、转发原博。
        """
        mid = str(raw_post.get("mid") or raw_post.get("id"))
        if not mid:
            logger.warning("[-] 跳过无 mid 的无效微博数据")
            return None

        # 检查是否已存在 (断点续传的关键)
        stmt = select(Post).where(Post.mid == mid)
        result = await db.execute(stmt)
        existing_post = result.scalar_one_or_none()
        if existing_post:
            logger.debug(f"[-] 微博 {mid} 已存在，跳过")
            return existing_post

        # 1. 解析并保存关联用户
        user_data = raw_post.get("user", {})
        user = await self.parse_and_save_user(db, user_data)
        if not user:
            return None

        # 2. 处理长文 (isLongText)
        text_content = raw_post.get("text", "")
        if raw_post.get("isLongText"):
            try:
                long_text_data = await self.client.get_json(
                    f"https://m.weibo.cn/statuses/extend?id={mid}",
                    referer=f"https://m.weibo.cn/detail/{mid}"
                )
                text_content = long_text_data.get("longTextContent", text_content)
            except Exception as e:
                logger.warning(f"[!] 获取长文失败 {mid}: {e}")

        # 3. 解析媒体文件 (pics / page_info)
        media_list: List[Media] = []
        
        # 图片
        pics = raw_post.get("pics", [])
        for pic in pics:
            url = pic.get("large", {}).get("url") or pic.get("url")
            if url:
                media_list.append(Media(
                    type="pic",
                    url=url,
                    width=pic.get("large", {}).get("width"),
                    height=pic.get("large", {}).get("height")
                ))
                
        # 视频 (page_info.type == 'video')
        page_info = raw_post.get("page_info", {})
        if page_info.get("type") == "video":
            video_url = (page_info.get("urls", {}).get("mp4_720p_mp4") 
                         or page_info.get("urls", {}).get("mp4_hd_url")
                         or page_info.get("media_info", {}).get("stream_url"))
            if video_url:
                media_list.append(Media(type="video", url=video_url))

        # 4. 处理转发原博 (retweeted_status)
        retweeted_id = None
        retweeted_raw = raw_post.get("retweeted_status")
        if retweeted_raw:
            # 递归解析原博 (注意：原博也可能有长文和媒体)
            retweeted_post = await self.parse_post(db, retweeted_raw)
            if retweeted_post:
                retweeted_id = retweeted_post.id

        # 5. 构建 Post 对象
        created_at = self.parse_weibo_time(raw_post.get("created_at", ""))
        search_text = clean_and_tokenize(text_content) # 🔥 调用 FTS5 分词
        
        post = Post(
            id=int(mid),
            mid=mid,
            user_id=user.id,
            created_at=created_at,
            text=text_content,
            raw_html=raw_post.get("text"),
            reposts_count=raw_post.get("reposts_count", 0),
            comments_count=raw_post.get("comments_count", 0),
            attitudes_count=raw_post.get("attitudes_count", 0),
            retweeted_status_id=retweeted_id,
            search_text=search_text,
            raw_json=str(raw_post) # 保留原始 JSON 兜底
        )
        
        # 关联媒体
        for m in media_list:
            post.media.append(m)
            
        db.add(post)
        logger.info(f"[+] 解析成功: {mid} ({created_at.strftime('%Y-%m-%d')})")
        return post

    # ==========================================
    # 4. 评论树解析
    # ==========================================
    async def parse_comments(self, db: AsyncSession, mid: str, max_pages: int = 5):
        """
        抓取并解析指定微博的评论。
        支持一级评论 + 二级评论递归。
        """
        logger.info(f"💬 开始抓取微博 {mid} 的评论...")
        fetched_count = 0
        
        # 抓取一级评论 (hotflow)
        page = 1
        max_id = 0
        while page <= max_pages:
            try:
                url = f"https://m.weibo.cn/comments/hotflow?id={mid}&mid={mid}&max_id_type=0"
                if max_id > 0:
                    url += f"&max_id={max_id}"
                    
                data = await self.client.get_json(url, referer=f"https://m.weibo.cn/detail/{mid}")
                
                comments_raw = data.get("data", [])
                if not comments_raw:
                    break
                    
                for c_raw in comments_raw:
                    await self._save_comment(db, mid, c_raw, parent_id=None)
                    fetched_count += 1
                    
                    # 抓取二级评论 (hotFlowChild)
                    child_comments = c_raw.get("comments", [])
                    for child_raw in child_comments:
                        await self._save_comment(db, mid, child_raw, parent_id=int(c_raw["id"]))
                        fetched_count += 1
                        
                # 更新游标
                max_id = data.get("max_id", 0)
                if max_id == 0:
                    break
                page += 1
                
            except Exception as e:
                logger.error(f"[!] 抓取评论失败 {mid} page={page}: {e}")
                break
                
        logger.info(f"💬 微博 {mid} 评论抓取完成，共 {fetched_count} 条")

    async def _save_comment(self, db: AsyncSession, post_mid: str, c_raw: Dict, parent_id: Optional[int]):
        """保存单条评论"""
        cid = int(c_raw.get("id"))
        if not cid:
            return
            
        # 去重检查
        stmt = select(Comment).where(Comment.id == cid)
        result = await db.execute(stmt)
        if result.scalar_one_or_none():
            return
            
        # 确保评论用户已入库
        user = await self.parse_and_save_user(db, c_raw.get("user", {}))
        if not user:
            return
            
        # 通过 mid 查找所属微博的 ID
        stmt = select(Post.id).where(Post.mid == post_mid)
        result = await db.execute(stmt)
        post_id = result.scalar_one_or_none()
        if not post_id:
            logger.warning(f"[-] 评论 {cid} 找不到所属微博 {post_mid}")
            return

        comment = Comment(
            id=cid,
            mid=str(c_raw.get("mid")),
            post_id=post_id,
            user_id=user.id,
            text=c_raw.get("text", ""),
            created_at=self.parse_weibo_time(c_raw.get("created_at", "")),
            parent_id=parent_id,
            like_count=c_raw.get("like_count", 0)
        )
        db.add(comment)

💡 核心设计亮点与避坑指南

Upsert 模式防止重复入库：
   在 parse_post 和 _save_comment 中，我们都先执行了 select 查询。这是断点续传的核心保障。当任务中断重启后，爬虫会重新请求之前的页面，解析器发现数据已存在就会自动跳过，绝不会报 Unique Constraint Violated 错误导致任务崩溃。

长文接口 (statuses/extend) 独立处理：
   微博列表接口返回的 text 字段对于长文是截断的（末尾带“全文”链接）。必须检测 isLongText 标志，并单独请求 /statuses/extend?id=xxx 才能拿到完整 HTML。这里使用了我们封装的 self.client.get_json，自动享受重试和风控保护。

极其鲁棒的时间解析器 (parse_weibo_time)：
   微博的时间字段不是标准 ISO 格式，而是人类可读的相对时间。这个静态方法覆盖了“刚刚/x分钟前/今天/昨天/MM-DD/YYYY-MM-DD”所有情况。注意：遇到“MM-DD”格式时，默认补全当前年份。如果你的归档跨度超过一年，建议在分页抓取时记录上下文年份进行动态修正。

FTS5 分词的无缝集成：
   在创建 Post 对象时，直接调用 search_text = clean_and_tokenize(text_content)。得益于我们在 database.py 中配置的 SQLite 触发器，当你执行 db.commit() 时，分词后的文本会自动同步到 posts_fts 虚拟表中，前端搜索功能开箱即用。

评论树的游标分页 (max_id)：
   微博评论不使用传统的 page=1,2,3，而是使用 max_id 游标。当 max_id == 0 时表示没有更多评论。同时，二级评论直接嵌套在一级评论的 comments 数组中返回，我们在同一个循环里一并解析入库，避免了额外的网络请求。

🧠 2. 核心状态管理：WebSocket 与任务控制

我们需要一个 Pinia Store 来全局管理 WebSocket 连接、实时日志和任务状态。

创建 src/stores/task.js：

import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import axios from 'axios'

export const useTaskStore = defineStore('task', () => {
  // 状态
  const status = ref('idle') // idle, running, paused, stopped, completed, failed
  const logs = ref([])
  const progress = ref({ page: 0, total_fetched: 0 })
  const captchaUrl = ref('')
  
  let ws = null
  let reconnectTimer = null

  // 计算属性
  const isRunning = computed(() => status.value === 'running')
  const isPaused = computed(() => status.value === 'paused')

  // 连接 WebSocket
  function connectWS() {
    if (ws && ws.readyState === WebSocket.OPEN) return

    // 注意：开发环境下 Vite 默认是 localhost:5173，FastAPI 是 8000
    const wsUrl = ws://localhost:8000/api/task/ws
    ws = new WebSocket(wsUrl)

    ws.onopen = () => {
      addLog('system', '✅ 已连接到后端服务器')
      clearInterval(reconnectTimer)
      // 心跳保活
      reconnectTimer = setInterval(() => {
        if (ws.readyState === WebSocket.OPEN) ws.send('ping')
      }, 30000)
    }

    ws.onmessage = (event) => {
      const msg = JSON.parse(event.data)
      handleMessage(msg)
    }

    ws.onclose = () => {
      addLog('error', '❌ 与后端断开连接，3秒后尝试重连...')
      setTimeout(connectWS, 3000)
    }
  }

  // 处理后端推送的消息
  function handleMessage(msg) {
    switch (msg.type) {
      case 'status':
        status.value = msg.data
        if (msg.data !== 'paused') captchaUrl.value = '' // 恢复后清空验证码
        break
      case 'log':
        addLog('info', msg.data)
        break
      case 'error':
        addLog('error', msg.data)
        break
      case 'progress':
        progress.value = msg.data
        break
      case 'captcha':
        captchaUrl.value = msg.data
        addLog('warning', '⚠️ 触发风控验证码，请手动完成！')
        break
    }
  }

  function addLog(level, text) {
    const time = new Date().toLocaleTimeString()
    logs.value.push({ level, text, time })
    // 限制日志数组长度，防止内存溢出
    if (logs.value.length > 500) logs.value.shift()
  }

  // API 调用
  async function startTask(uid) {
    await axios.post('http://localhost:8000/api/task/start', { uid })
  }

  async function stopTask() {
    await axios.post('http://localhost:8000/api/task/stop')
  }

  async function resumeTask() {
    await axios.post('http://localhost:8000/api/task/resume')
  }

  return { 
    status, logs, progress, captchaUrl, isRunning, isPaused,
    connectWS, startTask, stopTask, resumeTask 
  }
})

💡 前端架构避坑指南

WebSocket 自动重连机制：
   在 task.js 中，我加入了 ws.onclose 监听和 setTimeout(connectWS, 3000)。在开发时，如果你重启了 FastAPI 后端，前端会自动在 3 秒后重连，不需要你手动刷新页面，极大提升开发体验。

日志自动滚动 (nextTick)：
   在 Vue 中，当你向数组 push 新数据时，DOM 还没更新。必须使用 await nextTick() 等待 DOM 渲染完毕后，再去修改 scrollTop，否则日志总是“慢半拍”停在倒数第二行。

HTML 渲染与 XSS 防护：
   微博的 text 字段是包含 <a> 标签和表情图片的 HTML。我们使用 v-html 渲染它。安全警告：如果你打算把这个工具部署到公网，必须引入 DOMPurify 库对 post.text 进行清洗（DOMPurify.sanitize(post.text)），否则恶意微博可能包含 <script> 标签导致 XSS 攻击。作为本地个人工具，直接 v-html 是可以接受的。

图片网格的自适应 (grid-cols)：
   微博的图片排版很讲究：1张图是大图，2/4张图是两列，3/5/6/9张图是三列。在 WeiboCard.vue 中，我通过 computed 动态计算 Tailwind 的 grid-cols-* 类名，完美复刻了微博原生的九宫格体验。
